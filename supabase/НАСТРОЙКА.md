# Подключение заказов BESTI MOOD

Сайт использует публичный Supabase publishable key из `supabase-client.js`. Секретный `service_role` key в проект не добавлять и никому не отправлять.

## 1. Создать таблицы и защиту

1. Откройте Supabase → **SQL Editor** → **New query**.
2. Скопируйте и выполните весь файл `schema.sql`.
3. Скопируйте и выполните весь файл `catalog-seed.sql`.

Каталог в базе нужен, чтобы номер, название и цена заказа брались из серверной таблицы, а не доверялись данным из браузера. Если меняются цены, остатки или товары в `products-data.js`, выполните `node supabase/generate-catalog-seed.mjs`, затем заново выполните `catalog-seed.sql` в SQL Editor.

## 2. Настроить вход по почте и паролю

В **Authentication → Sign In / Providers** оставьте Email включённым. Чтобы регистрация работала без SMTP, отключите **Confirm email** и сохраните изменения. Тогда аккаунт создаётся сразу, но адрес почты не подтверждается. Сброс забытого пароля по email до настройки SMTP работать не будет.

Сайт использует email и пароль для входа; Telegram-ник сохраняется в профиле, чтобы менеджер мог связаться с покупателем.

## 3. Выдать менеджеру доступ

1. Менеджер должен один раз зарегистрироваться на сайте по своей рабочей почте и паролю. При выключенном **Confirm email** подтверждать почту не требуется.
2. В SQL Editor выполните команду, заменив email:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'manager@example.com';
```

3. Менеджер выйдет из аккаунта и войдёт на странице `admin.html` по рабочей почте и паролю. Если уже был авторизован до назначения роли, выйдет и войдёт снова.

`admin.html` показывает заказ, контакты и Telegram покупателя. Поиск принимает номер заказа, имя, телефон или Telegram. **Скачать для Excel** формирует CSV-файл в кодировке UTF-8, который открывается в Excel.

## 4. Опубликовать

Загрузите содержимое папки сайта в GitHub Pages. Папка `supabase/` нужна для настройки и не обязана публиковаться. В проект уже записаны URL и publishable key из настроек BESTI; секретных ключей в браузере нет.

Старые аккаунты и заказы из `localStorage` не переносятся в Supabase автоматически. Новые аккаунты, заказы и номера будут общими для сайта после выполнения SQL и публикации обновлённой версии.
